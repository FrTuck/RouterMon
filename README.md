# RouterMon — дашборд ресурсов и трафика роутеров OpenWrt

Лёгкий мониторинг для домашних и небольших офисных сетей на роутерах с **OpenWrt**: загрузка CPU, память, температура,
сеть, процессы, клиенты Wi-Fi и топ сайтов — по всем роутерам сети на одной странице. Ставится одной командой,
ничего не требует, кроме самих роутеров: ни облака, ни отдельного сервера, ни базы данных.

*A lightweight resource & traffic dashboard for OpenWrt routers (CPU, RAM, temperature, network, processes, Wi-Fi clients,
top sites). Runs on the routers themselves; one-command install. UI and docs are in Russian.*

Открывается в любом браузере локальной сети: **`http://<IP любого роутера с RouterMon>:8089/`** — с любого из них видны все.

## Возможности

- **Главная — все роутеры сети.** Карточка на каждый роутер: циферблаты CPU · RAM · Swap · t° CPU · t° Wi-Fi · Net,
  графики за час, диски, топ процессов, значок состояния («Норма», «Памяти мало», «CPU нагружен», «Горячо»…).
  Роутеры с RouterMon находят друг друга сами.
- **Страница роутера**, три вкладки:
  - **Обзор** — циферблаты со светофором, графики CPU, памяти, температуры, сети, swap и load за период от 15 минут
    до суток, интерфейсы, **топ адресов** (с какими сайтами обменивались клиенты этого роутера), таблица всех процессов;
  - **Трафик** — графики приёма и передачи по интерфейсам, таблица интерфейсов (назначение, скорость, пики, объём),
    адреса по сайтам или IP с фильтром по устройству;
  - **Клиенты** — кто подключён сейчас: хостнейм | IP | MAC, Wi-Fi-диапазон и SSID или проводной порт, сигнал, скорость
    канала, время в сети, объём за период.
- **Процесс** — CPU и память за час, команда, родитель и дочерние, потоки, порты и соединения.
- **Добавление роутеров со страницы**: «+ Добавить роутер» показывает найденные в сети роутеры OpenWrt без RouterMon
  и ставит его по SSH через мастер (объясняет, какие доступы нужны и зачем).
- Светлая и тёмная тема, работает на телефоне.

## Требования

- Роутер(ы) с **OpenWrt** и веб-сервером `uhttpd` (есть в стандартных сборках с LuCI), примерно 400 КБ свободной
  флеш-памяти. Проверено на OpenWrt 25.12 (aarch64, MediaTek MT7981); код — только `sh`/`awk` из busybox, без
  бинарных пакетов, поэтому от архитектуры не зависит.
- Доступ root по SSH к первому роутеру (пароль или ключ).
- ПК с Windows 10/11, Linux или macOS — только для установки на первый роутер.

## Установка

Коротко: скачайте репозиторий и запустите `install.cmd` (Windows) или `./install.sh` (Linux/macOS). Установщик предложит
адрес основного роутера (шлюз вашего ПК), спросит пароль root, поставит RouterMon, найдёт в сети другие роутеры с OpenWrt
и предложит поставить и на них. Подробно — в **[INSTALL.md](INSTALL.md)**.

## Что RouterMon меняет на роутере

Всё обратимо командой удаления (см. INSTALL.md).

- Файлы в `/etc/rmon-web/` и служба `/etc/init.d/rmon` (добавлены в `/etc/sysupgrade.conf` — переживают обновление прошивки).
- Отдельный экземпляр `uhttpd` на порту **8089**; LuCI и другие веб-серверы не затрагиваются (LuCI перезапускается на 2–3 с).
- Данные мониторинга — только в ОЗУ (`/tmp/rmon`, до ~4 МБ): час по 10 с и сутки по 1 мин. После перезагрузки история начинается заново.
- **Только на роутере, через который идёт интернет** (в таблице соединений есть трафик) — для топа адресов:
  включается учёт байт в conntrack (`nf_conntrack_acct`) и журнал DNS-запросов dnsmasq в ОЗУ (`/tmp/rmon-dns.log`,
  обнуляется каждые 10 с; по нему адреса подписываются доменами). Выключить: `sh /etc/rmon-web/lib/setup.sh dnslog off`.

## Безопасность и приватность

- **RouterMon рассчитан на доверенную (домашнюю) сеть: всё, что доступно со страницы, доступно любому устройству
  локальной сети.** Входа по паролю у страницы нет. Если в вашей локальной сети бывают посторонние устройства —
  гостевые, чужие, непроверенные, — выносите их в отдельную гостевую сеть или не ставьте RouterMon.
- API и страница отвечают **только устройствам локальной подсети** (`lan`) роутера, данные только читают.
  Действия (установка на другой роутер, убрать/вернуть роутер) принимаются только со страницы RouterMon (POST с JSON).
- Ничего не отправляется наружу: нет облака, телеметрии и внешних скриптов — страница самодостаточна.
- Мастер добавления роутера передаёт пароль root нового роутера от браузера к роутеру **по HTTP без шифрования**
  и нигде его не сохраняет. Пользуйтесь им только в доверенной сети (или ставьте с ПК установщиком — по SSH).
  Поставить RouterMon на другой роутер со страницы может любой в локальной сети, кто знает пароль root того роутера.
- Галочка мастера **«Разрешить постоянный доступ по ключу»** дописывает в `/etc/dropbear/authorized_keys` нового
  роутера открытый ключ роутера, с которого его добавляли. Это полный доступ root по SSH без ограничений:
  кто получит root на первом роутере, получит его и на втором. Без галочки ключ не сохраняется.
  Отозвать доступ: удалите эту строку из `/etc/dropbear/authorized_keys` второго роутера.
- Топ адресов и журнал DNS показывают, куда ходят устройства сети, — учитывайте это, если сетью пользуются другие люди.

## Как устроено

- Сборщик `web/lib/collect.sh` (служба `rmon`) раз в 10 с читает `/proc`, `/sys`, conntrack и `iw`, пишет снимки в `/tmp/rmon`.
- `web/cgi-bin/api` — CGI на `sh`/`awk`, отдаёт JSON: сводку, историю, процессы, трафик, клиентов, топ адресов.
- `web/index.html` — вся страница одним файлом, без зависимостей и сборки.
- `web/lib/setup.sh` — установка/удаление на самом роутере; его используют и установщики ПК, и мастер на странице.
- Роутеры находят друг друга по ARP-таблице и списку `/etc/rmon-web/routers.conf`. Браузер опрашивает каждый роутер
  напрямую, а если не пускает (блокировщик и т. п.) — через роутер, с которого открыта страница.
- CPU везде в процентах **всей** мощности роутера: все ядра, загруженные полностью, — это 100%.
- Клиенты роутера — Wi-Fi-станции его точек доступа и устройства на его LAN-портах; mesh- и GRE-интерфейсы считаются
  магистралью. Хостнейм — из статических хостов `/etc/config/dhcp`, у незнакомого устройства пусто.
- Топ адресов: прирост байт каждого соединения раскладывается по паре «устройство → удалённый адрес» в 5-минутные корзины
  за сутки. Трафик прокси (sing-box, xray и т. п.) и VPN-туннелей WireGuard/AmneziaWG не дублируется. Соединения короче
  10 с могут не попасть; устройства с глобальными IPv6-адресами учитываются неточно.

## Если что-то не так

| Признак | Что сделать |
|---|---|
| «Сборщик не работает» | `ssh root@<IP> /etc/init.d/rmon restart` |
| Роутера нет на главной | «+ Добавить роутер» → «Найдены в сети» или ввести IP (список роутеров обновляется раз в минуту) |
| «Данные ещё собираются…» | после установки или перезагрузки графикам нужно 20–30 с, топу адресов — около минуты |
| Мастер: «ключ SSH-сервера не совпадает» | роутер переустанавливали? Удалите его строку из `/root/.ssh/known_hosts` на роутере, с которого ставите |
| Топ адресов пуст | данные собирает роутер, через который идёт интернет; на mesh-узлах своей таблицы соединений нет — это нормально |
| Страница не открывается | ПК в той же подсети, что и роутер? Порт 8089 не занят? `ssh root@<IP> netstat -ltn \| grep 8089` |
